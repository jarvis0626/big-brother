## What changed

Online games normally contact servers and can use a wide range of ports. The model compares event patterns with older enterprise activity; it cannot decide whether a game server is trustworthy. This update makes that distinction clearer and corrects which connection snapshots enter scoring.

- **Behavior notes have their own place.** Differences from the trained reference appear as neutral, evidence-linked notes. They do not increase the Findings count. The separate **Findings** panel continues to show patterns identified by transparent evidence rules.
- **Attempted connections stay visible.** For polling TCP snapshots, only the `ESTABLISHED` state enters the model comparison. Attempts, closing connections and other states remain in the timeline and exported evidence.
- **Short sessions explain the wait.** The model requires sixteen earlier supported events plus a new one. Until then, there is no reference score or behavior note; the timeline and evidence rules remain available.
- **A new sample explains online activity.** Choose **Explore a replay → Online connections → Open replay** to inspect a behavior note. This is fabricated data and runs no network activity or sample program.
- **Everyday-data research is documented.** A small Windows Sysmon dataset was acquired and audited. It was excluded from behavioral training because it lacks original times, process identities, destination ports and TCP states. A separate local diagnostic helper preserves a privacy-reduced version of an explicitly selected session without fitting, calibration or upload.

The model weights and threshold are unchanged. This release does not claim retraining, reduced real-world malware false positives or measured malware-detection accuracy. It changes observation handling and the meaning presented to the user. A note or finding is not a malware verdict; a quiet list does not prove safety.

Older sessions refresh their notes and findings on first view using the same saved evidence. A paused session stays paused after that initial compatibility refresh.

## Keep using the familiar workflow

Use **Watch a process** to observe a program that is already running. **Select executable** chooses a file; **Launch and watch** explicitly starts it. Follow the process graph, inspect the timeline, open notes or findings and click their event references. **Export** saves a local JSON report. Sessions, retention settings, inert recording import and tray controls remain available.

Basic process and connection observation works without extra services. Broader file, Registry and DNS records need an already configured Sysmon channel. Big Brother does not install that privileged service automatically and does not block, quarantine or remove programs.
