The active model is **LANL temporal GRU event predictor**, version `lanl2015-v1-seed 1984`. It was actually trained on real process, network-flow and DNS records and evaluated on disjoint held-out hosts and later times. It reports event-sequence surprise as negative log likelihood in nats. It does not estimate the probability of malware. Low scores do not establish safety.

The experiment asks whether temporal event order helps predict the next host event compared with a feature histogram. It cannot answer whether process/file/network graphs improve malicious-behavior detection: this acquisition has no trustworthy attack labels, file evidence or process-family identifiers. The interface can display richer observed evidence; those fields do not become model inputs.

Ten fixed categories represent process start, process end, DNS, and seven network destination-port groups: web (80/443/8080/8443), SMB (139/445), remote services (22/3389), DNS (53), other service ports below1024, high ports, and anonymized/unknown ports. Usernames, process names, addresses, command lines and host identifiers do not become predictors. The model ignores file, Registry and process-access events. Category53 had no training observations; validation also had no remote-service targets. These groups need broader independent validation.

The trained baseline learns 8 centroids of 16-event category histograms with Laplace-smoothed next-category distributions. The neural model uses an 8-dimensional embedding and 16-unit PyTorch GRU. Both predict the same 8 targets with the same rolling 16-event contexts in each disjoint 24-event window. Centroids and distributions fit training only. Eight neural epochs used seed 1984, CPU training with 2 threads and Adam learning rate 0.005. Epoch 8 and the default model were selected by validation mean next-event loss. Thresholds were fixed at the 99th percentile of validation maximum target surprise before test evaluation.

The final test contains 11,888 target predictions in 1,486 windows. These are genuine held-out public telemetry results. The GRU improves next-event prediction loss in this subset; it provides no demonstrated malware-detection improvement. Exceedance fractions have unlabelled windows as their denominator and must never be called false-positive rates. No precision, recall, F1, PR-AUC, detection latency or false-alerts/hour is reported. [Saved metrics](../training/results/metrics.json) include per-category held-out losses, exact configuration, every epoch and limitations.

Training and preparation took 30.55 seconds on this Windows 11 machine, an AMD Ryzen 7 5800H with 16 logical CPUs; PyTorch 2.10.0+cpu, NumPy 2.4.3. Final sampled training RSS was 537.00MiB. Peak training memory was not measured. Baseline fitting took 0.45 seconds; the 8-epoch neural run took 23.08 seconds. The neural JSON artifact is 43,811 bytes; the baseline is 4,917 bytes. Standard-library inference for one 16-event prediction had median 2.740ms and p95 2.970ms over 30 samples. Complete score-call timings are saved separately in metrics; those use fabricated input solely to measure runtime, with no detection-accuracy claim.

The neural model is exported as checked JSON arrays and evaluated with standard-library arithmetic. Maximum category-probability difference from PyTorch was 2.822×10⁻⁷ across 32 actual validation contexts. Category probabilities are next-event predictions; the application exposes only surprise scores. The active artifact index records its SHA256, feature schema, real version and validation-selected threshold. Missing, corrupt or incompatible models expose `unavailable`; no rules replace them. The application evaluates up to 8 recent supported targets, takes their highest surprise and links the context/target event IDs as evidence. Short contexts are explicitly marked because held-out evaluation used 16 preceding supported events.

The model was trained on host-wide enterprise activity. A watched process and its descendants form a narrower observation stream, and polling misses brief network/process events. Process ancestry and network attribution are recorded collector evidence; they were not learned from this LANL subset. Personal Windows activity, source coverage changes, uncommon ports, short contexts and repeated rolling scoring can change alert rates. The threshold is not calibrated for application sessions. Use findings as investigation prompts supported by the recorded events.

Deterministic reference rules separately flag recorded behaviors such as startup-entry changes or activity after a parent exits. They have distinct evidence and scoring labels. They are not model replacements and have no measured malware accuracy. The fabricated installer/helper replay demonstrates both rules and the fixed trained scorer; no replay records are training or test data, and its score is never counted as real-world performance.

Reproduce acquisition/training with `python training/acquire_lanl.py --prefix-mib 4` then `python training/train.py --epochs 8 --seed 1984`. Run `python training/audit.py` to reproduce frozen subgroup analysis and inference timings without fitting or tuning. The application needs no PyTorch, NumPy, scikit-learn or external LLM installation. Raw datasets and the training checkpoint are not bundled.
